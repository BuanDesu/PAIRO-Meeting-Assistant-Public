# Windows 启动与打包测量

2026-10-13，在当前 Windows 电脑、Electron 44.4.5、0.2.0 成品上执行。每组两次：第一次使用新的隔离配置，第二次使用该配置并受操作系统缓存影响。计时从启动进程开始，到生产页面加载完成、原生信令 IPC 可用；没有采集媒体、连接手机或调用 AI。

| 方式 | 第一次 | 第二次 | 计入便携解压 |
| --- | --- | --- | --- |
| 清理依赖前的便携 EXE | 8.692 秒 | 8.643 秒 | 是 |
| 清理依赖后的便携 EXE | 9.054 秒 | 8.862 秒 | 是 |
| 同一目录包直接启动 | 0.474 秒 | 0.325 秒 | 否 |
| 新增 ZIP 实际解压后的目录程序 | 0.489 秒 | 0.264 秒 | 否 |

这组样本没有显示清理依赖改善启动速度。直接启动和便携启动的差异说明，后续启动优化应优先处理重复解压；不能把两次测量当作稳定的性能基准或跨电脑结论。

已增加 `win-x64-folder.zip` 下载选项：用户先解压整个目录，之后直接打开其中的 EXE，避免每次启动都重复解压。它与单文件 EXE 使用同一运行包；实际 ZIP 解压、两次启动、原生信令 IPC 和 EXE 旁 `PAIRO-data` 创建均已验证。ZIP 首次解压时间单独记录在报告，不包含于表中的启动时间。单文件 EXE 保留原来的临时解压及退出清理行为。

清理只影响桌面运行包：前端工具在构建时使用，打包后保留信令服务实际需要的 `ws`。应用目录从 239 个文件、2,085,522 字节降至 38 个文件、640,863 字节；EXE 从 116,652,857 字节降至 116,332,727 字节，减少 320,130 字节（约 0.27%）。Electron 运行时仍占主要体积。

## 重复测量

先运行 `npm run desktop:portable`，然后在 Windows 上执行：

```powershell
node scripts/measure-startup.mjs portable
node scripts/measure-startup.mjs directory --unpacked
node scripts/measure-startup.mjs downloaded-zip --zip
```

脚本将配置和 JSON 报告放在 Git 忽略的 `release/performance-qa/<名称>/`。使用新名称可创建新配置；重复使用已有名称会如实标记已有配置。测试独占本机调试端口 9226，端口已被占用时停止，不连接其他实例；完成后关闭本次测试程序。

若服务端新增运行依赖，需要调整桌面保留名单，并用真实目录包和 EXE 检查启动及信令，不能只检查构建成功。
