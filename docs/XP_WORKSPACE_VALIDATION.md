## 2026-10-15 真机短验收

- Android 16 手机从正式签名 0.2.0 / 2001 覆盖更新到 0.3.0 / 3001，无卸载；电脑地址、API 地址和模型名称逐项比对保留。Key 仅在会话内存，升级前结束旧会话后为空。
- 现场发现系统状态栏遮挡标题，改用 Capacitor SystemBars 的 CSS 安全区变量，在工作区外层预留系统区域。模拟安全区几何检查通过，同签名修复包更新后实际截图顶部正常。
- 用户确认三个页面可点击切换，手机键盘弹出时输入栏与底部导航均可见。
- 正式候选 EXE 分享指定单个测试窗口；用户允许麦克风。热点调整后沿用原房间建立加密 P2P 直连，视频 1 条、音频 2 条轨道均为 live。
- 主窗口收起托盘后，用户按实体 Num1：截图投送与自动回答成功，电脑无弹窗、不抢焦点、未播放声音。
- 实体 Num3 不唤出主窗口；用户主动恢复窗口后输入并发送生成问题，手机自动回答成功。再次收起后按 ↑/↓，手机回答区域上下滚动正常，房间始终保持连接。
- 实体 Num2：用户对电脑麦克风说测试语句，手机接收文字并自动回答；随后关闭，电脑状态确认不再转写。用户反馈文字为繁体；噪声下的精度未作定量评估，补充本机简体规范化。
- 简体修复：原生转写结果经固定版本 [opencc-js 1.4.2](https://github.com/nk2028/opencc-js) 的本机词典转换后再投送，不调用网络。4 项相关检查通过，包含取消后再次转写、繁体转简体及英文数字保留。直接加载新打包目录内后端，真实 CLI 识别生成中文 WAV，结果为“请介绍本次会议的目标并说明下一步安排”，工作目录清理正常。
- 一对一模式：新打包程序只发送视频 1 条、系统音频 1 条轨道；观察实际 getUserMedia 调用，麦克风请求为 0。专用窗口播放约 5 秒生成中文语音，经实际 Windows 系统音频回环、AudioWorklet 和本机引擎转写后投送，用户确认手机显示简体“请介绍本次会议的目标并说明下一步安排”并自动回答。投送计数为 1，随后关闭转写，电脑回答区仍为空。
